# /design-sync notes — mi-crm-next

## Repo shape (why the config looks the way it does)

- `src/design/` is **not** a real npm package: no `package.json`, no TypeScript, no build/`dist/`. The sync runs in **synth-entry mode** (`[NO_DIST]` on every build — expected, not a regression).
- `cfg.entry` (`src/design/dist/index.js`) **deliberately points at a path that doesn't exist**. It's only there so `package-build.mjs`'s own `PKG_DIR` resolution walks up from `dirname(entry)` and lands on the repo root's real `package.json` (`mi-crm-next`) — there's no `node_modules/mi-crm-next` to resolve `PKG_DIR` the normal way. Don't "fix" this by pointing it at a real file; it must stay a nonexistent sibling of the real source so the walk-up lands at repo root.
- `cfg.srcDir` = `src/design/components/core` (11 plain `.jsx` files, named function exports). Component discovery is regex/AST-based (`deriveComponentsFromSrc`), not `.d.ts`-based — any new component just needs a top-level `export function Name(...)` in that directory to be picked up on the next sync.
- No `@types/react` in the repo's `node_modules` → every build prints `[DTS_REACT]`. Harmless here (components have no real TS prop types to lose either way), but if this repo ever adds TypeScript to `src/design/`, install `@types/react` in the repo (not just `.ds-sync/`) before the next sync or prop extraction will silently degrade.

## `cssEntry` is a hand-maintained flat file — re-sync risk

`src/design/_ds_bundle_entry.css` does **not** exist for the app (nothing in `src/app/` imports it — `layout.js` imports `styles.css`/`components.css`/`forms.css` separately). It exists **only** for this sync, because `cfg.cssEntry` must resolve to ONE flat stylesheet with no further local `@import`s (the converter copies the file's raw bytes into `_ds_bundle.css`; it does not chase `@import`s to sibling files — see `[CSS_IMPORT_MISSING]`/`[CSS_PLACEHOLDER]`).

It's a straight concatenation, in this order: `tokens/fonts.css` (kept as a **remote** `@import` — fine, `[FONT_REMOTE]` is informational) → `tokens/colors.css` → `tokens/typography.css` → `tokens/spacing.css` → `tokens/radius-elevation.css` → `tokens/base.css` → `components.css` → `forms.css`. `app-shell.css` is **not** included (the app doesn't load it at root either — it's shell-nav-specific, not used by any of the 11 synced components).

**Re-sync risk**: if any of those 8 source files changes, or a new one needs including (e.g. a 12th component that reads classes from a file not in this list), `_ds_bundle_entry.css` must be **regenerated by hand** before rebuilding — nothing detects staleness automatically. Regenerate with:

```bash
cd src/design && { echo "/* generado para /design-sync */"; cat tokens/fonts.css tokens/colors.css tokens/typography.css tokens/spacing.css tokens/radius-elevation.css tokens/base.css components.css forms.css; } > _ds_bundle_entry.css
```

## Render check — never ran

No Playwright/Chromium in this environment (macOS 12 Monterey — a prior attempt this session to install Playwright for browser automation also failed on this same machine for the same OS reason). Every build/validate/resync ran with `--no-render-check`. **The 11 authored previews were never screenshotted, captured, or graded** — `package-capture.mjs` can't run without Chromium either. They compile and the render-agnostic checks (bundle syntax, CSS import closure, `.d.ts` parse, token references) are clean, but nobody has confirmed they *look* right.

**Action for the user**: open the project at `https://claude.ai/design/p/944dc20a-0d56-4b24-8500-64ae47354bff` and eyeball each of the 11 cards (or serve `./ds-bundle` locally with `node .ds-sync/storybook/http-serve.mjs ./ds-bundle` and open `.review.html`). Report anything that looks wrong (unstyled, wrong color, broken layout) and it gets fixed component-by-component.

## What this run did NOT touch — deliberate scope cut, not an oversight

The project **used to have** 3 hand-authored full-screen mockups (`ui_kits/crm/Dashboard.jsx`, `ProspectosList.jsx`, `ProspectDetail.jsx`, `BottomNav.jsx`, `index.html`) from an earlier session, built against the **old** Poppins/green token set. They were **deleted** in this sync (not regenerated) because they'd otherwise sit inconsistent with the new Inter/marigold tokens and mislead the design agent. `/design-sync`'s converter does not produce this kind of artifact at all (it only emits `components/<group>/<Name>/`) — full-screen mockups are hand-authored React uploaded directly via `DesignSync write_files`, outside this skill.

**Known follow-up, not started**: 8 of the 11 PRD screens have no mockup in this project at all (Login, Tareas del día, Nuevo prospecto, Registrar interacción, Pipeline, Reportes, Mi desempeño, Configuración) — the other 3 (Dashboard, Lista de prospectos, Ficha) just lost theirs to the deletion above. All 11 need hand-authored screen recreations against the current app (`src/app/(app)/**`) if/when that work happens.
